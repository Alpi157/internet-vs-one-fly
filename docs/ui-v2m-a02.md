## Rendering contract

Canvas dimensions derive from the actual CSS box and `devicePixelRatio`, with an 80 ms resize debounce. Requested dimensions are `ceil(css_width * DPR)` and `ceil(css_height * DPR)`. A uniform factor `min(1, sqrt(pixel_budget / requested_area))` preserves aspect ratio; each resulting backing dimension is floored. Thus the only permitted reduction is the declared pixel budget, with at most one pixel of rounding. The snapshot label backing always uses the requested dimensions and is never capped; visible HTML/SVG labels are resolution-independent. WebKit phone lab views show the same fixed 14 CSS px labels through the uncapped device-resolution canvas instead; this avoids its costly repaint of SVG over two stacked live views.

The game activity/anatomy raster and cached lab anatomy each have a **1,048,576-pixel budget**. The two simultaneous live lab activity layers each have a **32,768-pixel budget**. The lab's cached anatomy is rendered separately at device resolution up to its larger budget, so simplifying the expensive moving layer does not blur the anatomical skeletons. These are display budgets, with no effect on recorded spikes or executed scope. The initial combined one-megapixel and 262,144-pixel lab paths, uncached split layers and alternate compositor paths missed the WebKit DPR 2 FPS gate; their dry-run receipts are retained. The separate activity budget follows the previously measured a01 live-layer workload while the anatomical background gains device resolution. Individual lab diagram sections fit within 512 CSS px, centered in their existing balanced columns; the strength slider, registered chart and lesion cards retain the full-width story section. This avoids spending compositor work on wide black padding and keeps the native anatomical drawing readable. Visible labels and the 100 µm scale bar use HTML/SVG overlays at 14 CSS px, rasterized by the browser at device resolution; captions and other replay labels use fixed 12–16 CSS px. The full-device-resolution label canvas supplies deterministic saved snapshots and visible WebKit phone lab text. All other views use HTML/SVG overlays. The lab activity renderer caches the rasterization of every retained non-bridge segment per neuron and preserves per-pixel overlap counts; each frame updates alpha from that neuron's recorded spikes. Counts never combine different neurons. This avoids repeatedly rasterizing the same dense arbor geometry. All source anatomy and scientific traces stay unchanged.

A shared lab raster is used only if both its activity and independent static anatomy have sufficient actual sample density for the destination; it is never enlarged from a smaller source. Chromium and Firefox copy into the destination backing store, with letterboxing that preserves the anatomical transform. WebKit uses the existing local canvas stream for activity; its black matte is screened over the independently sharp anatomical background. Every visible flash still comes only from recorded spikes. Scrubbing recomputes deterministic decay through the selected recorded frame; there is no neural re-execution or temporal interpolation.

The timeline is drawn in CSS coordinates with 12 px track/time labels into a DPR-sized backing store. Its plot width follows its actual container; label and line sizes do not scale with that width. Exports use a declared standalone canvas size.
